# PQ 候选精确重排改进说明

## 1. 改进目标

基础 `pq` 使用 FAISS `IndexPQ`，以压缩码近似距离直接排序。改进版 `pq_rerank` 保留完全相同的 PQ 索引和训练参数，但查询时先取 `4 × K` 个 PQ 候选，再复用当前已校验数据集中的原始向量，按 L2、Cosine 或 IP 的真实数值重排并返回 K 项。

FAISS 官方文档说明 `IndexPQ` 在压缩域中比较 PQ 编码，索引码大小约为 `ceil(M × nbits / 8)` 字节/向量；本实现沿用这一索引，仅增加查询阶段的候选重排。[Faiss indexes](https://github.com/facebookresearch/faiss/wiki/Faiss-indexes)

## 2. Recall 不下降保证

固定同一查询、K 和无歧义的精确距离全序，记：

- `G`：全数据精确 Top-K；
- `P`：基础 PQ 返回的 Top-K；
- `C`：PQ 返回的 Top-`rK` 候选，`r >= 1`；
- `R`：在 `C` 中按精确距离重排得到的 Top-K。

因为 `P` 是 `C` 的前 K 项，所以 `P ⊆ C`。全局 Top-K 中的任意元素都不会排在非 Top-K 元素之后，因此 `R` 会优先取完 `C ∩ G`，得到：

```text
|R ∩ G| = min(K, |C ∩ G|) >= |P ∩ G|
```

所以在相同 PQ 候选序列下，精确重排的 Recall@K 不低于基础 PQ。若边界存在完全相同的精确距离，不同但等价的并列邻居可能改变基于 ID 的 Recall；API 因此同时返回本次实测的 `recall_non_decreasing`，不隐藏并列或实现差异。

最坏情况下，真正邻居没有进入 `C`，重排无法恢复它们，Recall 上界为 `|C ∩ G| / K`；下界则是基础 PQ 的 Recall。扩大 `r` 能扩展可恢复候选，但增加查询计算；当候选覆盖全部数据时会退化为精确扫描。本项目选择 `r = 4`，保留明确的精度/耗时折中。

## 3. 内存与耗时口径

- `index_bytes` 使用索引的稳定序列化字节数，不使用易受解释器、分配器和系统负载影响的进程 RSS。
- `pq` 与 `pq_rerank` 持久化完全相同的 PQ 码和码本，因此在参数相同时 `index_bytes` 相同。
- 重排向量来自已经加载且由数据集指纹保护的矩阵；加载持久化索引时重新绑定该矩阵，不在索引文件中复制一份。
- `avg_query_ms` 包含候选搜索和精确重排。重排一般增加查询耗时，系统报告实测差值，但不承诺任何机器上的固定延迟。
- `build_ms` 不包含评测时为统计 `index_bytes` 执行的序列化。

这三个指标分别回答检索质量、查询代价和索引存储代理，不把某一项的改善包装成三项同时改善。

## 4. 可复现回归证据

永久测试使用固定合成数据与查询集合：

```text
数据：NumPy RNG seed=1，640 × 16 float32 正态向量
查询：seed=123，无放回抽取 40 个细胞
度量：L2
K：10
PQ：M=8，nbits=4
重排候选：4 × K
```

当前固定依赖环境的参考结果：

| 方案 | Recall@10 | 序列化索引 | 结果 |
| --- | ---: | ---: | --- |
| PQ 基线 | 0.5975 | 3,670 B | 基线 |
| PQ + 精确重排 | 0.9625 | 3,670 B | Recall 提升 0.365（36.5 个百分点），索引字节不变 |

自动化测试断言相同查询摘要、相同 PQ 序列化指纹、Recall 至少提升 0.2、重排因子生效且索引字节相同；它不对墙钟时间设置脆弱阈值。真实数据与目标评审机器应通过页面重新运行，并保留数据集指纹、查询摘要、依赖版本和线程配置。

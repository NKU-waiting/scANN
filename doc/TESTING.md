# 测试与验收说明

## 质量门

后端质量门：

```bash
conda activate scann
cd backend
ruff check .
ruff format --check .
PYTHONDONTWRITEBYTECODE=1 pytest -q -p no:cacheprovider
```

前端质量门：

```bash
conda activate scann
cd frontend
npm run lint
npm test
npm run build
```

GitHub Actions 在 push 和 pull request 上执行相同流程。后端使用 Python 3.12，前端使用 Node.js 22.23.1。

## 测试隔离

后端文件测试使用 pytest 临时目录动态创建 SQLite、上传文件、索引和 `.h5ad`。测试结束后不保留数据库、索引、上传样本、日志或结果文件。前端测试运行于 jsdom，不启动真实浏览器或后端。

永久回归测试属于项目质量资产，可以提交。临时 smoke 脚本、curl 输出、构建目录、截图草稿和运行日志不应提交，验证后应清理。

## 功能验收路径

1. 全新数据库启动，登录 demo 管理员。
2. 上传一个小型 NPY 或 CSV 并激活。
3. 构建 HNSW/Cosine，按细胞查询并检查 Top-K。
4. 添加 `cell_type` 条件并确认所有返回项满足条件。
5. 保存索引，构建 Flat，再加载保存的 HNSW。
6. 重启后端，确认活动数据集恢复并能手动加载持久化索引。
7. 运行 Flat、IVF、HNSW、PQ、PQ 精确重排评测并查看 Recall/耗时/索引字节。
8. 查看 UMAP 查询点/结果高亮和查询/评测历史。
9. 切换到 demo，以管理员身份删除测试数据集并确认关联索引消失。

该路径只用于人工验收；不应把临时样本、脚本或输出加入提交。

## 性能评测口径

- 使用相同数据集、随机种子、度量、K 和查询集合。
- Flat 搜索结果作为 ground truth。
- 从 ground truth 和预测中按原排序移除查询细胞自身。
- 当 K 大于可用邻居数时，使用 `min(K, n_cells - 1)` 作为有效 K 和 Recall 分母。
- 查询时间只覆盖索引搜索调用；构建时间单独报告。
- `index_bytes` 使用稳定的序列化大小；数据集矩阵不重复计入索引字节，不能把该值解释成进程总 RSS。
- PQ 与 PQ 精确重排必须使用相同 `query_set_digest`；时间差只报告，不在自动测试中断言跨机器阈值。
- UMAP 首次 JIT、系统负载、CPU 线程和文件缓存会影响耗时，报告时必须说明环境。

项目不提交机器相关的固定性能数字。评审时应使用内置评测面板在目标环境复现实测，避免把某台设备的数字误当作通用保证。

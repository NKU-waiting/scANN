# scANN 全功能演示操作文档

本文档用于指导从打开项目开始，完成 scANN 全功能演示、报告截图采集和演示后收尾。所有路径均使用仓库相对路径，截图建议统一保存到 `doc/screenshots/`，便于后续写报告时引用。

## 1. 演示目标

本次演示需要覆盖以下功能：

| 模块 | 需要展示的能力 |
| --- | --- |
| 项目启动 | 后端 Flask API、前端 Vue 工作台正常启动 |
| 用户与权限 | 登录、注册、管理员用户管理、普通用户和管理员权限差异 |
| 数据管理 | demo 数据、主 H5AD 与补充 H5AD 上传、数据集列表、切换、删除 |
| 索引管理 | Flat/HNSW/PQ 等索引构建、索引状态、保存、加载、删除 |
| 查询检索 | 按细胞编号查询、按向量查询、Top-K、`cell_type` 条件检索 |
| 结果展示 | Top-K 表格、距离或得分条形图、类型分布、查询耗时 |
| 二维可视化 | UMAP/PCA 投影、查询细胞和结果高亮、图上点击查询 |
| 性能评测 | 多索引 Recall@K、查询耗时、构建耗时、索引字节、PQ 重排对比 |
| 多数据集联合检索 | 共享空间确认、联合索引构建、跨数据集结果来源追踪 |
| RAG 助手 | 自然语言查询、检索计划、证据表、引用、本地证据模式或 AI 模式 |
| 历史记录 | 查询历史、评测历史、管理员全局视图 |
| 工程质量 | 后端 Ruff/pytest、前端 ESLint/Vitest/build 通过 |

## 2. 截图规范

### 2.1 保存位置

建议先创建截图目录：

```bash
mkdir -p doc/screenshots
```

所有截图保存到：

```text
doc/screenshots/
```

### 2.2 命名规则

使用两位数字顺序编号，英文小写单词，用下划线连接：

```text
01_backend_started.png
02_frontend_started.png
03_login_panel.png
```

不要使用空格、中文文件名或本机用户名。报告中引用截图时直接写相对路径，例如：

```text
doc/screenshots/07_cell_search_results.png
```

### 2.3 截图隐私要求

截图前注意：

- 不要截到本机绝对路径、用户名、token、API key、私人数据文件名。
- 终端截图尽量裁剪掉命令提示符中的个人路径，只保留命令输出和成功状态。
- 登录截图不要截到明文密码。
- RAG provider 如配置了外部 key，不要截图环境变量或后端配置文件。
- 本演示使用 `data/liver.h5ad` 作为主数据集，`data/liver_IFALD.h5ad` 作为补充数据集；报告中应说明补充数据集来自 `data/补充数据集说明.txt`，用于跨数据集对比、索引动态增删和肝病相关分析演示。

### 3.1 打开项目

```text
backend/
```

### 3.2 激活环境

如果已经创建过环境：

```bash
conda activate scann
```

如果是第一次运行，按 README 安装依赖：

```bash
conda create -n scann python=3.12 -y
conda activate scann
cd backend
pip install -r requirements.txt
cd ../frontend
npm ci
cd ..
```

首次安装依赖时间较长，报告中通常不需要截安装过程，只需要截最终运行和测试结果。

### 3.3 确认主数据集和补充数据集

本演示直接使用 `data/` 中的两个 H5AD 文件，不再生成临时 CSV：

| 文件 | 演示名称 | 用途 | 默认向量字段 | 规模 |
| --- | --- | --- | --- | --- |
| `data/liver.h5ad` | `liver-main` | 主数据集，覆盖真实 H5AD 上传、索引、检索、可视化、评测和索引持久化 | `X_pca` | `69,032 × 30` |
| `data/liver_IFALD.h5ad` | `liver-ifald-supplement` | 补充数据集，覆盖跨数据集对比、联合索引、动态增删和肝病相关分析 | `X_pca` | `81,001 × 30` |

`data/补充数据集说明.txt` 对补充数据集的定位是：

```text
补充数据集用于跨数据集对比、索引动态增删等。
此数据集中包含部分肝病相关数据、如果有相关需求可以进行分析。
如果有需要可以自行补充其他数据集，但是要在文档中体现出来源。
```

演示前确认以下条件：

- 两个 H5AD 文件均位于 `data/` 下。
- 两个文件都包含 `obsm["X_pca"]`，系统默认读取该字段作为检索向量。
- 两个文件都包含 `obs["cell_type"]`，用于条件检索、结果分布和 RAG 证据摘要。
- 两个文件较大，浏览器上传时需要提高后端上传大小限制。
- 两个文件合计 150,033 个细胞，RAG 同时分析两个数据集时需要提高自然语言分析细胞数限制。

## 4. 启动后端和前端

### 4.1 启动后端

打开第一个终端：

```bash
conda activate scann
cd backend
SCANN_MAX_UPLOAD_BYTES=4294967296 SCANN_MAX_ASSISTANT_CELLS=200000 python run.py
```

看到服务监听本机端口后，保留该终端运行。

这里设置两个演示环境变量：

- `SCANN_MAX_UPLOAD_BYTES=4294967296`：允许上传约 4 GiB 文件，覆盖两个 H5AD 的浏览器上传需求。
- `SCANN_MAX_ASSISTANT_CELLS=200000`：允许 RAG 同时分析主数据集和补充数据集的 150,033 个细胞。

## 12. RAG 单细胞分析助手演示

若未配置外部 AI provider，页面会显示“本地证据模式”。这仍然是有效演示，因为系统会真实检索并返回确定性证据摘要。

本章同时勾选两个 H5AD 数据集时，后端启动命令必须包含 `SCANN_MAX_ASSISTANT_CELLS=200000`，否则默认 100,000 个细胞上限会拒绝 150,033 个细胞的联合 RAG 分析。

### 12.1 相似细胞自然语言查询

操作：

1. 在 RAG 助手中勾选 `liver-main` 和 `liver-ifald-supplement`。
2. 共享向量空间标识填写：

```text
liver-x-pca-main-supplement-v1
```

3. 勾选共享空间确认框。
4. 显式查询来源选择 `liver-main`，显式细胞编号填写 `0`。
5. 自然语言问题输入：

```text
请找出与主数据集第 0 个细胞最相似的 5 个细胞，并总结它们的细胞类型和来源数据集。
```

6. Top-K 输入 `5`。
7. 距离度量可选择 `L2`，或保持“从问题推断”。
8. 点击“提交自然语言分析”。
9. 查看回答、检索计划、证据表和引用。

建议截图：

| 截图文件名 | 截图内容 |
| --- | --- |
| `26_rag_similar_cell.png` | RAG 相似细胞问题的计划、回答、证据和引用 |
